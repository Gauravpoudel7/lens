# Plan: daily posts for the Lens bot

Status: proposal, not built. Follows the rules in `AGENTS.md`: prove before posting, no word "scam", no buy/sell advice, mock data labeled, tests next to the code.

## Goal

Lens posts at least 3 times every day, even when discovery finds no new LOW or HIGH coin.

| Post | Time (UTC) | Source |
| --- | --- | --- |
| 🛡️ Safety tip | 09:00 | Fixed list, rotating |
| 📊 Daily recap | 14:00 | Lens's own activity today, or the market if Lens was quiet |
| 📘 Crypto term in one line | 19:00 | Fixed list, rotating |
| 🔥 / ⚠️ Coin calls and warnings | Anytime, up to 8 a day | Already built (`runOutboundCycle`), only needs turning on |

## Why the bot doesn't post today

1. Outbound is off by default: `OUTBOUND_ENABLED=false`, `OUTBOUND_DISCOVER=false`.
2. Posting only happens while the worker runs (`npm run worker`, or `LENS_ROLE=all` on the server).
3. Discovery posts only LOW or HIGH coins. Most new coins score MEDIUM, so some days nothing is posted.
4. Discovery reads DexScreener profiles and boosts. Boosts are paid promotions.

## Phase 1: tips and terms (about half a day)

### New files

| File | What it contains |
| --- | --- |
| `packages/core/src/editorial/content.ts` | 15 tips and 14 terms, reviewed against the copy rules |
| `packages/core/src/editorial/compose.ts` | `composeTip(i)`, `composeTerm(i)`: build the post text and check it fits 280 characters |

| `packages/core/src/editorial/cycle.ts` | `runEditorialCycle(deps)`: pick, prove, post, save |
| `*.test.ts` next to each | See Tests below |

### How one post goes out (same order as coin posts)

```
1. Is a post due?   now ≥ slot hour, and no post of this kind today
2. Build the text   next tip or term in the rotation
3. Prove it         buildProofPayload(text) → deps.proofs.publish()
                    proof fails → stop, do not post (AGENTS rule)
4. Save the record  status "proved"
5. Post to X        deps.x.post(text)
6. Update record    status "posted" + xPostId (or "post_failed" + error)
7. Move rotation    setCursor("editorial_tip_index", i + 1), only after success
```

### Hook into the worker

In `packages/core/src/poll.ts`, inside `pollOnce`, after `runOutboundCycle(deps)`:

```ts
const editorial = await runEditorialCycle(deps);
if (editorial.posted > 0) log("posted editorial", editorial);
```

No new process or timer. It runs in the existing poll (every 180 seconds by default).

### Database

New model in `prisma/schema.prisma`. It is separate from `Check`, so tips and recaps do not change the scorecard win rate.

```prisma
model EditorialPost {
  id          String   @id
  kind        String   // tip | term | recap
  day         String   // UTC yyyy-mm-dd
  text        String
  contentHash String
  payload     String
  txSignature String
  cluster     String
  xPostId     String?
  status      String   // proved | posted | post_failed
  error       String?
  createdAt   DateTime @default(now())

  @@unique([kind, day]) // one of each kind per day, even across restarts
}
```

Add to the store interface (`packages/core/src/store/types.ts`), in both `packages/db/src/store.ts` and `MemoryStore`:

- `saveEditorial(record)`
- `updateEditorial(id, patch)`
- `getEditorial(kind, day)`
- `listEditorial({ day? })`

Then `npm run db:push`. Postgres is generated by `scripts/prepare-schema.mjs` as usual.

### Settings

Add to `loadConfig()` in `packages/core/src/config.ts`, `.env.example`, and the README table.

| Variable | Default | Meaning |
| --- | --- | --- |
| `EDITORIAL_ENABLED` | `false` | Master switch |
| `EDITORIAL_KINDS` | `tip,term,recap` | Which post types to send |

| `EDITORIAL_TERM_HOUR_UTC` | `19` | Term time |
| `EDITORIAL_MAX_LATE_HOURS` | `6` | If the worker was down, still post up to this many hours late; after that, skip the day instead of posting several at once |

### Copy rules

- No word "scam".
- No buy or sell advice.
- No links, so each post costs $0.015 instead of $0.20.
- Each post fits 280 characters (X counting: most emoji count as 2).
- The recap ends with `Not financial advice.`

### Content to start from

Tips:

1. If the creator can still mint new coins, they can print more and dump them on you. Check that mint authority is off.
2. If the creator can freeze coins, they can stop you from selling. Check that freeze authority is off.
3. A coin that's only a few hours old is the riskiest kind. Waiting a day costs you little and can save you a lot.
4. If 10 wallets own most of a coin, they can crash the price whenever they want.
5. Low liquidity means it's hard to sell. Before you buy, ask: could I get out if I needed to?
6. "LP burned" or "LP locked" in a post means nothing until you see it on-chain. Ask for the transaction.
7. Never sign a transaction you don't understand. Wallet drainers look like normal "claim" buttons.
8. Free airdrop in your wallet you never asked for? Don't touch it. Many are bait for a drainer site.
9. Many coins share the same name. Always check the contract address, not just the $TICKER.
10. If an influencer says "100x, don't miss it", ask who is selling to you right now.
11. Never share your seed phrase. No real support team will ever ask for it.
12. Check where a link really goes before you click. Fake sites copy real ones letter by letter.
13. Only put in what you can afford to lose. New coins can go to zero in minutes.
14. Snipers often buy most of a coin in the first seconds. If a few wallets bought at launch, be careful.
15. "Can't sell" coins exist. If no exchange route lets you sell, it's a trap.

Terms:

1. Rug pull: the creator takes the money out of the coin and disappears, leaving everyone else with worthless coins.
2. Liquidity: the pot of money that makes buying and selling possible. Low liquidity = hard to sell.
3. Mint authority: permission to create new coins. If it's still on, the supply can grow anytime.
4. Freeze authority: permission to freeze people's coins so they can't move or sell them.
5. Market cap: price × number of coins. It's not money in the bank, just what the coins are "worth" on paper.
6. Slippage: getting a worse price than you expected because the price moved while your trade went through.
7. Honeypot: a coin you can buy but can't sell. The trap closes after you get in.
8. Sniper: a bot or insider that buys a new coin in its first seconds, often to sell to you later.
9. Bonding curve: pump.fun's launch system: the price rises as people buy, before the coin gets a normal pool.
10. Contract address: a coin's unique ID on the blockchain. Names can be copied; addresses can't.
11. Seed phrase: the 12 or 24 words that control your wallet. Whoever has them owns your money.
12. Exit liquidity: the people who buy so insiders can sell. If you don't know who that is, it might be you.
13. DYOR: "do your own research". Good advice, but most people don't know what to check. That's why we exist.
14. Whale: a wallet holding a huge amount of a coin. When it sells, the price feels it.

## Phase 2: daily recap (about half a day)

### Option A: Lens's own day (preferred)

Used when Lens checked at least 3 coins that UTC day. Data comes from the store, so no new API.

```
📊 Lens today
• 23 coins checked
• 6 HIGH · 11 MEDIUM · 6 LOW
• Most asked: $BONK
• Every answer proven on Solana
Not financial advice.
```

### Option B: the market (fallback)

Used when Lens checked fewer than 3 coins.

```
📊 Solana today (trending coins)
• Top gainer: $X +120%
• Most traded: $Y ($4.5M)
• Newest: $Z (9 hours old)
• 2 of 10 can still mint new coins ⚠️
Not financial advice.
```

Needs `listTrendingSolana()` in `packages/core/src/discover.ts`, reading GeckoTerminal's free trending pools
(`https://api.geckoterminal.com/api/v2/networks/solana/trending_pools?include=base_token`, about 30 requests a minute),
skipping wrapped SOL, USDC and USDT. Mint and freeze status come from `provider.getToken()` for the top 5 only.
